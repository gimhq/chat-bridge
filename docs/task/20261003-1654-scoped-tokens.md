## Description

The API has one bearer token (`server.token`) that sees and does everything. The user asked for
several tokens aimed at different consumers, each limited in which contacts it may talk to and
which messages it may read and search.

Acceptance:

- The existing `server.token` keeps full access and is the only token that manages tokens.
- Additional tokens are created, listed and revoked through the API; each carries an allowlist
  of persons, contacts and chats.
- A scoped token can list, read, search and send only inside its allowlist; everything else
  answers `404` or `403` as specified in the plan, and events are filtered the same way.
- Covered by store, core and server tests, including attempts to reach data outside the scope
  through every route family (chats, messages, search, contacts, persons, media, events).
- `docs/api.md` §10 and `docs/storage.md` describe the feature.
